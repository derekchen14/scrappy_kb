# Alembic Migrations Setup

## Overview

Alembic is now configured for database migrations. All models are organized in `common/models/` directory.

**Migration Strategy:**
- **DEVELOPMENT**: Run Alembic commands manually via Docker
- **PRODUCTION**: Alembic runs automatically on startup (via `entrypoint.sh`)

## Directory Structure

## Running Alembic Commands via Docker

### 1. Create Initial Migration (Autogenerate)

```bash
docker exec scrappy_kb_app alembic revision --autogenerate -m "Initial migration"
```

This will:
- Scan all models in `common/models/`
- Compare with current database state
- Generate migration file in `alembic/versions/`

### 2. Apply Migrations (Upgrade)

```bash
docker exec scrappy_kb_app alembic upgrade head
```

### 3. Revert Last Migration (Downgrade)

```bash
docker exec scrappy_kb_app alembic downgrade -1
```

### 4. View Migration History

```bash
docker exec scrappy_kb_app alembic history
```

### 5. View Current Revision

```bash
docker exec scrappy_kb_app alembic current
```

## Common Workflows

### Adding a New Model

1. Create new model file in `common/models/`
2. Import it in `common/models/__init__.py`
3. Generate migration:
   ```bash
   docker exec scrappy_kb_app alembic revision --autogenerate -m "Add new model"
   ```
4. Review the generated migration file
5. Apply migration:
   ```bash
   docker exec scrappy_kb_app alembic upgrade head
   ```

### Modifying an Existing Model

1. Edit the model file in `common/models/`
2. Generate migration:
   ```bash
   docker exec scrappy_kb_app alembic revision --autogenerate -m "Update model fields"
   ```
3. Review and edit the migration if needed
4. Apply migration:
   ```bash
   docker exec scrappy_kb_app alembic upgrade head
   ```

### Creating a Manual Migration

```bash
docker exec scrappy_kb_app alembic revision -m "Description of change"
```

Then edit the generated file in `alembic/versions/` to add your migration logic.

## Important Notes

- **Always review autogenerated migrations** before applying them
- Alembic might not detect all changes (e.g., table renames)
- Keep migrations in version control
- Never edit applied migrations - create new ones instead
- The old `models.py` file is still present but not used - all code now imports from `common.models`

## Configuration

### Environment Variables

**Database Configuration:**
```env
POSTGRES_HOST=localhost
POSTGRES_USER=my_user
POSTGRES_PASSWORD=my_password
POSTGRES_DB=my_database
POSTGRES_PORT=5432
```

**Migration Control:**
```env
ENVIRONMENT=development  # Manual migrations via docker exec
# OR
ENVIRONMENT=production   # Automatic migrations on startup
```

- Configuration is in `alembic.ini`
- Environment setup is in `alembic/env.py`
- Automatic migration logic is in `entrypoint.sh`

## Troubleshooting

### "Target database is not up to date"
```bash
docker exec scrappy_kb_app alembic stamp head
```

### "Can't locate revision identified by 'xyz'"
Check that all migration files are present in `alembic/versions/`

### "Multiple heads" error
Merge the heads:
```bash
docker exec scrappy_kb_app alembic merge heads -m "Merge migrations"
```
